# システム境界の案 v3（taigaの決定を反映）

2026-10-23 作成・更新。スレッド「システム化の範囲」。サービス名は コビトサポート（kobITo Support。10/24変更、商標・ドメイン確認中で変わる可能性あり）。図解は [system-boundary-v3.html](system-boundary-v3.html)。v2（[system-boundary-v2.md](system-boundary-v2.md)）からの変更：基幹に申込フォーム・請求書の発行・マイページ・決済機能（KOMOJU API）を入れ、スプレッドシートで始める案は取り下げ、プレオープンから小さなアプリとして作る。台帳5つ、既製に任せるもの、人がやることは v2 のまま。

## 0. 決まったこと（taiga 2026-10-23）

- KOMOJUはAPIで基幹の中の決済機能にする。申込のあと、初月分の請求書を送り、入金の確認で契約が成立する（カードは請求書のリンクからKOMOJUの支払い画面に進み、そこで定期課金も登録）
- カードは毎月自動で課金。**カード情報はこちらに一切残さない**（KOMOJUの定期課金に任せ、ずれは運用でカバー）
- カードが決済できなかったときは、翌日と3日後に、LINEとメールで知らせる
- コンビニ払いを追加し、コンビニと銀行振込は毎月お客様が支払う。銀行振込はCingulataの口座を案内（KOMOJUは通さない）
- 手数料：コンビニの**発行手数料はお客様の負担**。決済手数料（カード・コンビニの率）はこちらが負担し、料金に含める
- 請求書は**自動で発行**（確認なし）。インボイスは登録済みで、登録番号は実装の担当に渡す
- マイページで**見積の了承までできる**（最初から）
- マイページのログインは**メールアドレスとパスワード**。LINEを連携するとLINEでもログインできる
- パートナー報酬の基準は**税込み**

## 1. 基幹の部品

| 部品 | 使う人 | やること |
|---|---|---|
| 申込フォーム | お客様 | プラン、請求先、支払方法（カード／銀行振込／コンビニ）、紹介コード、規約・ポリシーへの同意。送信で顧客・契約に入り、同意の日時と規約の版が残る。送信後、当社が初月分の請求書を送り、入金の確認で契約が成立する。項目は要件定義書2章（F-／C-） |
| 決済機能（KOMOJU API） | お客様（裏側でKOMOJU） | カード：請求書のリンクからKOMOJUの支払い画面でカードを入力（番号などはこちらに残さない）、初月分を決済（同時に定期課金を登録）、以降はKOMOJUの定期課金で毎月自動課金。コンビニ：毎月、支払い番号を作ってお客様が払う（発行手数料はお客様負担）。入金通知（Webhook）で請求・入金を更新しクレジットを付与。銀行振込はこの機能を通さない |
| マイページ | お客様 | 契約、今月のクレジット、依頼の状況、請求書と支払い、**見積の了承**。ログインはメールとパスワード、LINE連携でLINEからも |
| 請求書の発行 | （自動） | 月初に全店の請求書を自動発行 → PDFと支払いの案内を送る。管理画面から取り消して出し直せる |
| 管理画面 | taiga | 顧客一覧と状態、依頼の記録（見積の作成・完了）、銀行振込の入金確認、請求書の一覧と取り消し、報酬の計算結果 |
| 台帳5つ | 裏側 | 顧客・契約／依頼／クレジット／請求・入金／紹介・報酬。列と独自ルールは v2 の4章 |

## 2. KOMOJUで調べたこと（公式、2026-10-23に確認）

| こと | わかったこと | 使い方 |
|---|---|---|
| 定期課金（支払いリンク型） | カードのみ。毎週・毎月・毎年。登録した日と同じ日に課金。取り消しは管理画面から。日付の指定、お試し期間、終了日、お客様自身の変更は、まだできない | **使う**（カード情報はKOMOJUだけが持つ）。ずれは運用でカバー（3章） |
| カードの登録（長期トークン） | Customerを作ってIDを保存し、あとでPayment: CreateにそのIDを渡して課金できる | 使わない（カード関連の情報をこちらに持たない方針） |
| コンビニ払い | APIで対応。期限や入金通知の細かい仕様は作るときに確認 | 毎月、支払い番号を作って案内 |
| 銀行振込 | 確認した公式ページには出てこない | 使わない（Cingulataの口座を案内） |
| 手数料の率 | 初期費用・月額なし、決済ごとの手数料のみ。率は公式ページに書かれていない | 契約前に確認 |

出典：[Subscription Payment Links](https://doc.komoju.com/docs/subscription-payment-links)、[Long-term Tokens](https://doc.komoju.com/docs/long-term-tokens)、[KOMOJU API](https://en.komoju.com/integrate/api/)。サブスクリプションAPIのリファレンス本体は読み込めなかったので、作るときに確認する。

## 3. 運用でカバーすること（KOMOJUの定期課金の制約）

| ずれること | 運用での扱い（案） |
|---|---|
| 課金日が申込日と同じ日になる（毎月1日ではない） | クレジットは月初に付与し、課金日より前でも使える（規約 第11条3項「当社の判断で確認前の利用を認める」の運用）。請求書には課金日を載せる |
| 金額の変更（プラン変更は翌月から） | 変更の前に、KOMOJUの定期課金の金額を更新する。更新のしかたはAPIで確認 |
| 追加クレジット（4,000円） | 定期課金には含めず、買うたびに一回払いで払ってもらう（マイページから） |
| 課金の失敗 | 翌日と3日後に、LINEとメールで知らせて再度の支払いをお願いする。再試行のしくみ（KOMOJU側が自動か、支払いリンクを送るか）はAPIで確認 |
| 解約 | 解約の月の末で定期課金を止める（お客様自身ではできないので、管理画面から止める） |

## 4. マイページで見られるもの

| 項目 | 表示 |
|---|---|
| 契約 | プラン、契約日、次の請求日、状態（利用中／解約予定） |
| 今月のクレジット | 今月の数、使った数、残り、使える期限 |
| 依頼の状況 | 受付済み／見積・了承待ち／作業中／完了、目安日、使ったクレジット |
| 見積の了承 | 見積（必要なクレジット数・目安日）を見て「了承する」を押す。日時が残る。届いたらLINEで通知。了承前は消費しない（規約 第8条） |
| 請求書と支払い | 月ごとの請求書（PDF）、支払い済み／未払い、支払いの案内 |
| 手続きの案内 | 追加クレジット・プラン変更・解約は「LINEで連絡」（追加クレジットは②でマイページから購入、プラン変更・解約は③で画面に） |

## 5. 請求書の発行で守ること

- **インボイス：** 登録済み。請求書に登録番号、取引の日付、内容、税率ごとの合計と消費税額、宛名。登録番号は実装の担当に渡す。書き方の最終確認は税理士に。
- **税込の料金：** 5,000／10,000／15,000円、追加4,000円。税抜と消費税（10%）の内訳を出す。
- **番号と控え：** 連番で重複させない。発行後は書き換えず、取り消して出し直す（自動発行なので、管理画面から取り消せるようにする）。控えの保存期間は税理士に確認。
- **コンビニの発行手数料：** コンビニ払いの請求書には、月額とは別の行で「コンビニ払い手数料」を載せる。金額は未定。消費税の扱いは税理士に確認。
- **15日ルール：** 15日以降に始めた初月の扱いを、金額とクレジットの期限の両方に反映。
- **支払い：** カードは毎月自動課金。コンビニ・銀行振込は、請求書に支払い番号・振込先を載せて毎月お客様が払う。決済手数料はこちら負担で料金に含める。

## 6. 段階

| 段階 | 作るもの |
|---|---|
| ① プレオープンまで | 申込フォーム、決済機能（カードの毎月自動課金、コンビニ払い、入金通知で自動付与）、カードが失敗したときの通知（翌日・3日後、LINEとメール）、台帳5つ、請求書の自動発行、マイページ（見る・支払う・見積の了承）、管理画面（銀行振込の入金確認を含む）、LINEへの通知（見積・請求） |
| ② PoC中（〜20社） | 依頼の状況が変わったらLINEで通知、追加クレジットをマイページから購入、パートナーの紹介リンク、報酬の明細 |
| ③ そのあと | プラン変更・解約の申出を画面で、パートナー用のページ |

## 7. 決めたいこと

1. コンビニの発行手数料の金額と、請求書での見せ方（おすすめ：請求書に「コンビニ払い手数料」を別の行で載せる。金額はKOMOJUの手数料を確認してから決める。消費税の扱いは税理士に確認。お客様負担なので、規約第11条5項、特商法表記、申込フォームにも書く必要がある）

## 8. 作る前に確認すること

1. KOMOJUの加盟店審査：カードの取り扱いに承認が必要（公式ページより）。日数がかかるので、WBSの「決済サービス選定」と同時に早めに申し込む
2. KOMOJUの定期課金APIの仕様：金額の変更、課金日、失敗したときの再試行、入金通知。3章の運用が成り立つかを確認する。成り立たない場合は相談する
3. KOMOJUの手数料率とコンビニの発行手数料の額：採算の確認に必要
4. パスワードの扱い：自作で保管せず、既製の認証の仕組みを使う。管理画面は2段階認証にする
5. 個人情報の扱い：お客様情報の保管・削除、バックアップを、プライバシーポリシーに合わせる
