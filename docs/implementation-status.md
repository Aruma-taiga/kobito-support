## 外部仕様の確認記録（KOMOJU）

- Webhookは `X-Komoju-Signature` のHMAC-SHA256で原文バイト列を検証する。配信IDと本文のイベントIDを混同しない。[公式Webhook仕様](https://docs.komoju.com/en/docs/introduction/core-concepts/webhooks)
- Hosted PageのSessionは請求番号を `payment_data.external_order_num` で渡せる。[Hosted Page](https://docs.komoju.com/en/docs/integration-guides/web-integrations/hosted-page/standard-mode)、[Session作成](https://ja.doc.komoju.com/reference/createsession-1)
- Hosted Sessionの `customer_payment` とSubscription APIの組合せが公式仕様上の候補。初回決済後の二重課金防止、次回の課金起点・月末・09:00の扱い、生成されるイベントの対応は加盟店テストで確認するまで有効化しない。カード情報や決済方法トークンを当アプリで受け取るフォームは作らない。[Customer mode](https://docs.komoju.com/en/docs/integration-guides/web-integrations/hosted-page/customer-mode)、[Subscription作成](https://ja.doc.komoju.com/reference/createsubscription-1)
- 外向きPOSTの `X-KOMOJU-IDEMPOTENCY` とWebhookイベントの重複排除は別の仕組み。[公式冪等性仕様](https://docs.komoju.com/en/docs/introduction/core-concepts/idempotent-requests)

上記は公開仕様の確認であり、加盟店アカウントでの動作検証・本番利用の承認を意味しない。

## W1（KOMOJU試作）の実測結果（2026-11-01、テストモード）

テストモードのキーで、セッション・カード支払い・顧客モード・定期課金を実際に試した結果。本番キーでは実施していない。月末日・失敗後の再試行は未確認（下記）。

**確認できたこと**
- 支払いのセッション（Hosted Page）に請求番号を `payment_data.external_order_num` で載せると、取得時にも、支払い後の `payment.captured` の通知にもそのまま入る。通知の `total`（税込）は送った金額と一致し、`captured_at` が入る。K1 が照合に `total` を使うのは正しい。
- **`external_order_num` は加盟店内で一度使うと二度と使えない**（取消後・金額変更・metadata 追加でも2回目は 422）。末尾に別の文字を足せば作れる。→ 請求番号に識別子を付けて送り、受け取り側で外す形に修正（本PR）。
- **カードが拒否されても、セッションは未完了（pending）のまま**で、お客様は同じ画面でやり直せる。`payment.failed` のあとに、やり直しの成功で `payment.captured` が同じ請求番号で届く。失敗→支払い済みの遷移（`failed>paid`）で正しく処理される。
- 定期課金（Subscriptions）と顧客モードは利用可能。顧客モードのカード登録画面には「今後の支払いに備えて支払い方法を保存します」の同意チェックが必須。

**定期課金を採用する場合の重要な制約**
- 定期課金は**作成した瞬間に最初の1回が課金される**（`subscription.captured` と `payment.captured`）。
- 定期課金が生む `payment.captured` には `external_order_num` も metadata も入らない（null）。請求書への結びつけは、`subscription.captured`（定期課金のオブジェクトで、作成時に付けた metadata を保持）と、契約に保存する定期課金のIDで行う必要がある。K1 は現状この経路に未対応。
- 課金日は作成日と同じ日。`day` の指定は効かない（作成日が1日だったため、月末の挙動は未確認）。**月末（29〜31日）の課金日の扱いは、その日に再試験が必要。**
- 失敗時の自動再試行：定期課金のオブジェクトに `retry_count`・`retry_at` があるが、失敗するカードでの動作は未確認（テスト環境の失敗カードでは顧客登録の段階で止まる）。

**その他**
