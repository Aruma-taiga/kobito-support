# 請求書 PDF の保管

`PdfStore` は `put(objectKey, bytes)` と `get(objectKey)` の境界です。`GcsPdfStore` は非公開バケットへの Cloud Storage JSON API の media upload / download を使います。API が顧客スコープを確認してから取得し、ブラウザへ配信します。このアダプター自体は認可を行いません。アップロードは `ifGenerationMatch=0` で既存オブジェクトの上書きを拒否します。既存キーへの再試行は取得したバイト列が完全に同じ場合だけ成功し、異なる場合は固定エラーで拒否します。

Cloud Run の実行サービスアカウントに付与した権限を使い、Google metadata server からアクセストークンを取得します。トークンは期限の 60 秒前までメモリにキャッシュし、同時の取得要求は共有します。認証失敗後の次回呼び出しはトークンを再取得します。外部リダイレクトを拒否し、各リクエストは本文読み取りまで既定 8 秒で中断します。エラーには固定コードのみを含め、トークン・オブジェクト名・プロバイダー本文を含めません。

`fetcher` と時計の注入を使った単体試験で、HTTP 形式、キャッシュ更新、同時更新、エラー、中断を確認しています。実際の GCS、IAM、Cloud Run metadata server は未検証です。バケット作成・権限設定・本番での利用開始は別途承認と外部検証が必要です。

アップロードと DB のコミットは単一トランザクションにはできません。呼び出し側は PDF ごとの固有キーを用い、既存の請求書のオブジェクトを上書きしないでください。アップロード後に DB 更新が失敗すると参照されないオブジェクトが残る場合があります。自動削除や補償削除はこのアダプターでは行いません。請求書の保存期間を保護するため、孤立オブジェクトの削除は DB の参照と保存要件を確認した運用手順で扱います。

`PostgresPdfStore` は既存の `invoice_documents` に PDF と SHA-256 を保存するローカル方式です。キーは `invoices/<UUID>.pdf` に限定し、読み出し時にハッシュを確認します。既存キーは上書きせず、同一バイト列だけを再試行として受け入れます。請求書作成トランザクション内では `PostgresPdfStore.putInTransaction(client, key, bytes)` を使うと、請求書と PDF を同時にコミットできます。単体試験の SQL モックは、実 DB のトランザクション・制約の検証を代替しません。
